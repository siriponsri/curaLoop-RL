# Contributing

Start with `START_HERE.md` and the active protocol. Report a defect with the exact release, scenario, expected behavior, observed public events and reproduction steps. Remove private molecular/customer information before opening a public issue. Preserve an export of the failing run when its data may be shared.

Use small coherent changes. Scientific changes need a new configuration/schema or method identity and focused evidence; documentation changes need current links and accurate status. Do not rewrite historical evidence to make a new implementation appear compatible. Preserve the MIT license and third-party attribution.

For a code contribution run relevant Python/frontend checks and state what was actually tested. Rebuild frontend/dist for UI changes. For a research contribution provide data rights, source/split hashes, baseline matching, all valid runs and interpretation limits. For a literature addition verify the source and identify its version/read level. No copied full article or unverified binary belongs in a pull request.

The project is initially maintained by one owner. A contributor need not introduce a complex approval process for routine improvements. Open a scoped issue or PR when collaboration helps; identify any decision that genuinely changes the research or product scope. Support is best effort until a separate commercial agreement exists.
