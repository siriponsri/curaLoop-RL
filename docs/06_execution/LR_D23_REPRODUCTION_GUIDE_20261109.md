# LR-D23 reproduction and evidence boundary

The delivered code implements one residual candidate, two fixed training rounds
and conditional D3 transfer. It is not permission to rerun closed campaigns,
reuse an old clock or open protected data. The release, frozen source/matrix
hashes, technical admission and aggregate receipts establish the executed scope.

## Inspect public evidence

Start with the LR-D23 results and owner checkpoint linked from HANDOFF.md. The
directory `docs/evidence/lr-d23-20261109-v1` contains only aggregate results,
source/experiment hashes and closure receipts. Individual molecules, private
Oracle inputs, model artifacts, event traces, SSH permits and downloaded reading
PDFs are intentionally local. A hash is provenance, not an independent validation.

The exact matrices are frozen before outcomes. They are generated by
`research/lr_d23_v1/matrix.py`; the implementation and selected-method comparison
are in `docs/03_research/LR_D23_ALGORITHM_AND_FREEZE_20261109.md`.

## Recalculate the primary aggregate locally

After complete return, an authorized reviewer with the private local evidence
can compare a pure recalculation against the public JSON:

```powershell
rtk proxy .venv\Scripts\python.exe tools/lrd23_reproduce_aggregate_v1.py .local/lr-d23-20261109-v1/D2-rows-private.json docs/evidence/lr-d23-20261109-v1/D2-aggregate-v1.json
```

This command does not contact dr-train, fit a model, choose a new molecule or
read final outcomes. Transfer aggregates, if assigned and completed, use their
matching private rows/aggregate files and `--transfer`. Do not label an unrun
cell as reproduced. Full trace/source/resource validation is a separate closure
audit; agreement of two aggregate files alone is insufficient.

## Re-executing a scientific campaign

A new campaign requires its own owner-approved release, fresh owned namespace,
budget/deadline and outcome-blind calibration. The old LR-D23 root is closed
after complete return and exact cleanup. Initialization/dispatch/return tools
are records of the executed version, not general-purpose resume commands.
Preserve the original masks, exposed/protected roles, held-out-component
exclusion, source pins and every negative or failed attempt.

The fresh CPU account retains complete booked envelopes, including failures and
utilities. Report physical worker measurements separately from that conservative
account. Scientific CPU excludes setup/offline training; include all costs when
discussing compute economics. Neither quantity is a wet-lab cost estimate.

## Product and paper use

The aggregate-only EN/TH evidence card and strict JSON schema live in
`research/product_handoffs/lr_d23_v1`. They are an offline adapter handoff, without
runtime integration or UI acceptance. The English paper insert preserves the
scientific disposition and biological limits. M3, independent/domain review,
actual product integration and journal submission require later decisions.
