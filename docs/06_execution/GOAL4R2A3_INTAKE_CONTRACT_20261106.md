## Gates before an outcome request

1. **Source/intended use:** retain primary policy evidence and per-AID notices.
   Distinguish NIH programme provenance from a blanket licence. Only an explicitly
   supported internal noncommercial computational qualification scope may pass;
   unresolved/contradictory notices quarantine the AID. Publication, raw-row
   redistribution and commercial reuse remain separately unresolved. Code MIT
   and article CC BY do not confer underlying row rights.
2. **Programme/endpoint:** decode raw project-category and unit enums only from
   a pinned official NCBI schema. Preserve missing/other separately. Bind source
   script column names to actual description TIDs with ambiguity rejected.
   AID counts or provider names are not biological-family certificates.
3. **Protected targets/structures:** reuse hash-verified feature-only canonical
   identities and typed target/family metadata, without reading label arrays or
   reopening the FS-Mol assay archive. Quarantine protected or unresolved target
   relationships before selecting an activity source. Obtain SID/CID/structure
   metadata first; exclude exact canonical matches to the protected feature panel
   before requesting observations. Ambiguous/no-structure identifiers are excluded.
   This is an exact-overlap control, with no chemical-OOD claim.
4. **Immutable request plan:** freeze the selected AIDs, endpoint/TID mapping,
   permitted IDs, input hashes, request/byte ceilings and exposure record after
   metadata/protection checks but before the first activity response.
5. **Engineering:** execute the twelve prespecified cases and obtain scoped
   review of request filters, protection/privacy and missingness handling.

If any gate fails, retain the evidence and continue independent permitted audits.
Do not bypass source denial, substitute a different population or acquire a full
activity table merely because a filtered operation is unavailable. Material
rights/source/population changes are owner decisions.

## Bounded sample and transport

- At most twelve candidate stage pairs, chosen by source/endpoint/protection
  metadata and a frozen outcome-independent order. Report the actual verified
  biological groups; twelve pairs do not imply twelve independent families.
- At most128 selected common tested SIDs per pair, with deterministic seeded
  hash ordering fixed before outcomes. Use identifier/structure metadata to
  enforce protection first. Never resample to obtain more positives.
- At most96 new PubChem PUG requests across identifier/structure and filtered
  activity operations; at least1.1 seconds between requests. Each request has
  a bounded timeout, no automatic retry after403/429, and no bulk fallback.
- Only the exact existing PubChem skill client may issue PUG calls. Preserve its
  source hash. Keep full responses private. An isolated transport adapter around
  that unchanged client must enforce fixed host/path/options, no redirects and
  streaming decoded-byte limits:16MiB each and256MiB cumulative. Verify those
  behaviors in the frozen engineering checks; max_items is not a download cap.
- Up to32 UniProt metadata-only requests through its exact existing skill client
  may resolve reviewed protein RefSeq cross-references/families. Use fixed field/
  accession batches, release receipts, the same bounded transport and no sequence
  or assay queries. This does not access activity data or change the population.
- Add a source-derived exact-operation request submanifest before any permitted
  network intake; unspecified activity paths/options remain disabled.

The first activity request is a bounded canary. Verify requested/returned source
identity and identifier coverage before proceeding. Typed parsing checks row IDs
before interpreting activity values. Unexpected/protected IDs, schema changes,
rate limits or ambiguous qualifiers stop the affected intake. Retain errors and
quarantine any unexpected bytes without sending outcomes to agent context.

## Observation, population and reconstruction

Keep source-tested, exact numeric, bounded/censored, qualitative, inconclusive/
invalid, missing and not-followed-up distinct. Missing is not zero or negative;
there is no default potency imputation. Preserve original units, qualifiers,
readout/TID, replicate provenance and endpoint direction. Conflicting replicates
remain explicit; never retain the best activity through outcome-sorted deduplication.

The sample is conditional on source follow-up and permitted observable support.
Report denominators for metadata-listed, sampled, protected/excluded, returned,
interpretable and eligible records. Source binary outcomes and numeric potency
are different candidate endpoints; selecting a future scientific endpoint needs
the A3 review checkpoint. Simulated assay cost/time remains unmeasured.

Current-source qualification may test feasibility using a dated PubChem snapshot
with version/revision concordance checked against SI. It does not certify exact
historical row bytes. The A2 description-selector negative control remains
binding: HTTP200 does not establish requested historical revision enforcement.
Report exact-historical and named-current-source readiness separately; no current
snapshot silently replaces the future paper-exact design.

## Cases, outputs and stop

Freeze twelve engineering cases before implementing the new qualification
package: strict records/IDs, rights scope, protected identities, unresolved family
quarantine, outcome-independent sampling, bounded identifier filters, row-ID-first
privacy, replicate conflicts, exact/censored/missing units, source identity,
coverage denominators and exposure/report boundaries. Synthetic fixture checks
are engineering evidence only.

Outputs: source/programme/rights register, endpoint contract, protection manifest,
request/access ledger, aggregate observation/attrition report, resource profile,
GO/NO_GO/UNKNOWN gates and a justified next study or explicit failure decision.
No raw activity/compound rows, publisher text or private dependencies enter public
Git. Every owned remote file is returned and reread before exact scoped cleanup.
Stop at A3 owner review, its CPU cap or absolute deadline, whichever comes first.
