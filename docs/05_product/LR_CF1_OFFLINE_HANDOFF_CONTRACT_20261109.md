# LR-CF1 offline product evidence contract

The deliverable is a standalone EN/TH report and strict aggregate evidence card.
It is separate from the running CuraLoop screening engine and four-screen UI.
No live connector, laboratory queue, new policy or product dataset is activated.

## Report information

- Keep the retrospective development status and observation-supported population
  visible before the result table. Identify six campaigns, four provider blocks,
  one annotation component and the pinned processed-repository source.
- Show all 18 ranker/operator arms for every selected campaign and fixed budget.
  The default 10% view is a reading example, not an outcome-selected endpoint.
  An equal-campaign view may summarize these six fixed campaigns descriptively.
- H counts source-confirmed positives. D counts fixed positive structure groups;
  D(FP) is the prespecified sensitivity. H/B and D/B are counts per confirmation.
  Do not display these as money, clinical efficacy or simulated elapsed time.
- Present the mean and observed range across five conditional seeds. Never
  relabel that range a biological-population interval. No compound identity,
  structure, individual assay outcome or unpublished pending result belongs in
  this aggregate payload.
- Source 0 combines inactive and inconclusive. Missing confirmation is outside
  the supported universe, never converted to 0. The source observation process
  limits what the report can say about a full prospective library.
- Distinguish completed baseline feasibility from a novel-method claim. The
  report does not certify a new selector, independent evaluation or journal
  readiness. Both languages must retain those distinctions.

## Eventual screen mapping, proposed only

| Screen | Allowed future mapping | Evidence still needed before integration |
| :--- | :--- | :--- |
| Discovery Overview | Dataset/version, study status, actual aggregate counts and limitations | Owner-approved adapter and source/hash provenance checks |
| Digital Twin Simulation Lab | Explain how a confirmation plan differs from the existing retrospective event replay | Actual engine-event contract; no fabricated CF1 queue/delivery events |
| Benchmark Arena | Separate CF1 ranker/operator H/D comparisons from old Random/Greedy/AL/RL campaign results | Dataset/endpoint separation, actual filters and EN/TH interaction verification |
| Compound Explorer | No individual CF1 rows supplied by this handoff | Explicit row-level data authority and existing hidden-outcome API protections |

These are proposed mappings, not features implemented by LR-CF1. The existing
application remains governed by its current simulator and privacy contracts.

## Artifact and validation boundary

The report reads its embedded aggregate payload offline and performs no team or
laboratory write. The evidence card must pass the semantic contract and strict
JSON schema. Unexpected raw-label, compound-row or pending-result fields must be
rejected. The completed package records its actual schema, source hashes and
EN/TH browser checks separately from generation success. Scientific cells are
independently recalculated before they populate the report.

Before a later integration, the owner chooses a bounded phase and source-use
scope. Internal derived-report preparation does not establish raw redistribution
or commercial data clearance. No customer, business ROI, team deployment or
clinical-validation claim follows from this offline package.
