# START HERE | CuraLoop-RL Portfolio Handoff v3 (audited)

**Owner intent:** build an independent, personal Git portfolio project showing pharmaceutical R&D decision-support to a professional audience potentially including colleagues at the Government Pharmaceutical Organization (GPO), Thailand. **This is NOT an official GPO system**, not a validated drug discovery result, and not an operational Digital Twin.

**Pack created:** 2026-11-03 (Asia/Bangkok). **Mode:** specification + QA + agent prompts + paper bibliography. **Not** runnable application; GPT Work will build the starter project, Codex will continue. It contains **zero publisher/article PDF binaries**: PDFs were not retrievable in this sandbox, and a bibliographic link does not confer redistribution rights.

## Five-minute handoff

1. Open `audit/AUDIT_REPORT.md` and `audit/RELEASE_VALIDATION.md` to understand what was checked, which earlier weaknesses were corrected, and unresolved limitations.
2. Read `GOAL.md`, `PLAN.md`, `docs/PRODUCT_REQUIREMENTS.md`, `docs/ARCHITECTURE.md`, `docs/DATA_GOVERNANCE_FOR_DEMO.md`, `docs/RESEARCH_PROTOCOL.md`, `docs/EVALUATION.md`, `docs/TWIN_VALIDATION.md`.
3. **Copy all of `prompts/01_GPT_WORK_MASTER_PROMPT.md` into ChatGPT Work**, attach this ZIP, and ask it to create a real local Git repository, a working offline demo and tests. Do not accept a README-only implementation.
4. Work writes **`HANDOFF_TO_CODEX.md` in the actual newly built repository**, containing exact local path, branch + SHA, executed commands, tests, screenshots provenance, TODOs and limits.
5. Open the actual repository in Codex and paste `prompts/02_CODEX_MASTER_PROMPT.md`. Codex starts by running and auditing the existing implementation; no wholesale rewrite.
6. Use `docs/DEMO_STORYBOARD_TH.md` and `docs/PRESENTATION_7_MIN_TH.md` to present only *measured capabilities* of the demo.

## Priority and scope contract

**Working offline app > scientifically correct simulator > fair baseline comparison > documented datasets > RL > twin maturity > publication.** All claims must be marked DONE / TESTED / NOT_RUN / PLANNED. A real RL result is not required to finish the first demo, but a policy named RL must not be shown as implemented unless it truly was trained and tested.

## Hard boundaries

- No internal GPO data, staff/patient information, LIMS, formulas, logos, cloud credentials, deployment, or branding in this personal repo without explicit authorization and applicable rights review.
- No external GitHub push, public repo creation, cloud hosting, paid service, GPU job or company-system connection without the owner's explicit authorization.
- Historical labels used for evaluation are **private to the simulator oracle until revealed**; no target/test label leakage to the policy or preprocessing.
- Synthetic cost/time/noise is a scenario assumption, **not** a measured cost, manufacturing saving or actual assay fidelity.
- A retrospective virtual screening simulator is *digital-twin-ready*, not a validated live Digital Twin.
