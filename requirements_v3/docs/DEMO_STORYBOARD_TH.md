# Demo storyboard — สำหรับพอร์ตโฟลิโอ (5–7 นาที)

**ผู้ชม:** คนทำงานสายเภสัชกรรม / R&D / ผู้บริหารที่ไม่จำเป็นต้องรู้จัก RL

**ก่อนเริ่ม:** ใช้ตัวอย่าง SYNTHETIC_ONLY หรือ dataset ที่ตรวจสิทธิ์แล้วและเตรียมไว้ในเครื่อง ไม่ต้องใช้อินเทอร์เน็ต อธิบายว่าเป็นโครงการส่วนบุคคล ไม่มีการเชื่อมต่อกับระบบของ อภ.

## Scene 1 — Pain point (0:00–0:50)

**บนจอ:** Overview + ภาพกระบวนการ `Candidate library → Policy → Virtual assay → Feedback → Better choices`.

**พูด:** 'สมมติว่ามีสารให้พิจารณาหลายพันรายการ แต่ทดลองได้เพียงบางส่วน เราจะเลือกสารใดก่อนเพื่อใช้ทรัพยากรให้เกิดประโยชน์?' ยังไม่ใช้ศัพท์ PPO, reward shaping หรือ molecular docking.

## Scene 2 — Configure the experiment (0:50–1:45)

**บนจอ:** เลือกตัวอย่างข้อมูล `Synthetic demo`, ตั้งจำนวนการทดสอบ 20 จาก 200 สาร, batch 5, seed 42, delay 1 รอบ. ตัวเลขเป็น **ตัวอย่างการตั้งค่า** ไม่ใช่ค่าจริงขององค์กร.

**พูด:** 'ระบบนี้ใช้ผลทดสอบที่ซ่อนไว้ในตัวจำลอง และจะเปิดเผยเฉพาะเมื่ออัลกอริทึมตัดสินใจเลือกสารนั้น'

## Scene 3 — See the loop (1:45–3:00)

**บนจอ:** กด Run หนึ่งรอบ, โชว์ selected IDs, pending/delivered results, budget remaining, chosen strategy and reasons. Advance next round.

**พูด:** 'AI ไม่ได้เห็นคำตอบล่วงหน้า เมื่อมีผลกลับมา AI จึงนำข้อมูลมาเรียนรู้เพื่อเลือกสารในรอบถัดไป' ห้ามโชว์ label truth ของสารที่ยังไม่เลือก.

## Scene 4 — Compare alternatives (3:00–4:30)

**บนจอ:** Run Random / Greedy / Uncertainty บน seed และ budget เดียวกัน; ดูเส้นจำนวน confirmed hits vs tests.

**พูด:** 'ผลลัพธ์นี้เป็นเพียง benchmark ของข้อมูลตัวอย่าง ไม่ใช่หลักฐานว่าช่วยประหยัดค่าใช้จ่ายจริง หากเปลี่ยนข้อมูลหรือ seed วิธีที่ชนะอาจเปลี่ยนไป'

## Scene 5 — RL + Digital Twin road ahead (4:30–5:45)

**บนจอ:** Scenario controls + stage badge `Retrospective simulator` and future maturity timeline. If trained RL not yet implemented, show a roadmap panel explicitly `Planned`, *not a performance graph*.

**พูด:** 'ขั้นต่อไปคือให้ Agent เรียนรู้ว่าจะใช้กลยุทธ์ใดกับสถานการณ์ใด และเพิ่มการจำลองคิวทดลอง เวลารอผล ความคลาดเคลื่อน และงบประมาณ หากจะเรียกว่า Digital Twin ของห้องปฏิบัติการจริง จำเป็นต้องมีข้อมูลจริงและการตรวจสอบเพิ่มเติม'

## Scene 6 — Engineering evidence (5:45–7:00)

**บนจอ:** Git commit, tests passing, reproducible run command, exported JSON report and source labels.

**พูด:** 'จุดแข็งของงานนี้ไม่ใช่แค่หน้าจอ แต่คือโค้ดที่ทดสอบซ้ำได้ มีประวัติการตัดสินใจและสามารถให้ผู้เชี่ยวชาญตรวจสอบวิธีคำนวณได้'

## คำถามที่คาดว่าจะถูกถาม

**'ช่วยค้นพบยาใหม่ได้เลยหรือไม่?'** — ยังไม่ได้ ระบบนี้สาธิตการเลือกสารสำหรับ *assay screening* ผลบวกไม่ได้ยืนยันประสิทธิผลหรือความปลอดภัยของยา.

**'เชื่อมต่อข้อมูลของ อภ. หรือไม่?'** — ไม่เชื่อมต่อ เป็นโครงการส่วนบุคคลและใช้ข้อมูลเปิดหรือจำลองเท่านั้น.

**'RL ดีกว่าแบบเดิมเท่าไร?'** — จะรายงานเฉพาะผล benchmark ที่ทำจริง พร้อมเงื่อนไขและช่วงความไม่แน่นอน หากยังไม่ฝึก RL ให้ตอบว่ากำลังพัฒนาต่อ.

**'เป็น Digital Twin แล้วหรือยัง?'** — ยังเป็น replay simulator ที่ออกแบบให้พัฒนาไปสู่ digital twin ได้ในอนาคต.
