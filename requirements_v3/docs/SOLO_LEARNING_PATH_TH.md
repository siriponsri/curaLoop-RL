# คู่มือเริ่มต้นสำหรับ Solo Developer ที่ยังไม่เชี่ยวชาญ Drug Discovery

เป้าหมายคือ **เรียนเฉพาะความรู้ที่จำเป็นต่อการออกแบบระบบ** ไม่ใช่ต้องเรียนเภสัชศาสตร์ทั้งหมดก่อนเริ่มเขียนโปรแกรม

## 1. เข้าใจสิ่งที่กำลังคัดเลือก

- **Compound (สาร):** โครงสร้างเคมีที่อาจถูกทดสอบว่ามีฤทธิ์ตาม assay ที่กำหนด; ยังไม่ใช่ 'ยา'
- **Target:** โปรตีนหรือระบบชีวภาพที่เกี่ยวข้องกับคำถามทดสอบ
- **Assay:** วิธีทดสอบที่มีนิยาม endpoint ชัดเจน เช่น การยับยั้งกิจกรรมที่วัดได้ภายใต้เงื่อนไขหนึ่ง
- **Active / Inactive:** ป้ายกำกับผลใน assay นั้น ๆ; ไม่ยืนยันความปลอดภัยหรือใช้รักษาโรคได้
- **SMILES:** ข้อความใช้แทนโครงสร้างโมเลกุล; ต้อง parse/validate ก่อนใช้จริง
- **Molecular Fingerprint:** เวกเตอร์ตัวเลขแสดงส่วนย่อยโครงสร้างเพื่อใช้เปรียบเทียบหรือฝึก ML
- **Scaffold:** โครงสร้างแกนของโมเลกุล; ใช้สร้างชุดทดสอบยากขึ้นด้วย scaffold split

## 2. เข้าใจหลัก ML ที่ต้องใช้

- **Supervised learning:** ทำนาย Active/Inactive จากตัวอย่างที่ทราบผลแล้ว
- **Uncertainty:** ความไม่มั่นใจของการทำนาย; ไม่เท่ากับความผิดพลาดของเครื่องมือทดลอง
- **Active Learning:** เลือกตัวอย่างใหม่มาเพิ่มข้อมูลเพื่อฝึกโมเดลให้ดีขึ้น
- **Bandit:** เรียนรู้ว่าจะเลือกทางเลือกใดจากรางวัลที่เห็น; โจทย์นี้ใช้เลือกกลยุทธ์การคัดสาร
- **RL:** เพิ่มการพิจารณาผลต่อสถานะและรางวัลในอนาคต; ซับซ้อนกว่า bandit
- **Oracle:** ใน simulator คือกลไกเปิดเผย label ที่เก็บไว้ล่วงหน้าเมื่อทดลองจำลอง; ไม่ใช่ AI ทำนายผลใหม่

## 3. เข้าใจ Digital Twin ไม่ให้ใช้คำผิด

**Simulator:** ระบบจำลองผลตามข้อมูลประวัติศาสตร์/สมมติฐาน โดยไม่เชื่อมกับกระบวนการจริง

**Digital shadow:** รับผลใหม่จากระบบจริงทางหนึ่ง แต่ไม่ได้ปิดวงจรการตัดสินใจและการทดสอบจริงครบถ้วน

**Digital Twin:** ในระดับที่มีความสมเหตุสมผล ต้องระบุคู่เทียบทางกายภาพ (เช่น ขั้นตอน screening ในห้องปฏิบัติการ), มีข้อมูลที่อัปเดตสม่ำเสมอ ตรวจสอบความแม่นยำ/ความไม่แน่นอน และผลจากการตัดสินใจย้อนกลับเข้าวงจรจริง แนวแบ่งขั้นนี้เป็นกรอบของโครงการ ไม่ใช่มาตรฐานทางกฎหมาย

## 4. ลำดับการเรียนที่ทำไปพร้อมเขียนได้

**M1:** Python, pandas, pytest, Git; สร้าง synthetic fixture และทดสอบ budget ledger

**M2:** Random/Greedy/Uncertainty พร้อมแสดงกราฟจริงจาก event log และการป้องกัน label leakage

**M3:** RDKit, SMILES, assay/target labels, dataset provenance; เริ่ม LIT-PCBA ชุดเล็กที่ถูกสิทธิ์

**M4:** Active Learning vs Bandit vs RL; multi-seed และการทดสอบ baselines แบบยุติธรรม

**M5:** Delayed events, noise, cost assumptions, uncertainty and Digital Twin verification; นำเสนอ demo อย่างไม่กล่าวอ้างเกินข้อมูล

## 5. คำถามที่ต้องตอบได้ในการนำเสนอ

1. ทำไม AI จึงเลือกสารตัวนี้? (ตอบจาก policy และข้อมูลที่เห็นในขณะนั้น)
2. ถ้าไม่ใช้ AI จะเปรียบเทียบกับอะไร? (Random, Greedy, Uncertainty และ baseline ที่เข้มแข็ง)
3. ผล Active เป็นผลทดสอบจริงหรือสมมติ? (แยก source type ทุกครั้ง)
4. ต้นทุนนี้คือค่าใช้จ่ายจริงหรือไม่? (หน่วยสมมติสำหรับการจำลอง)
5. นี่เป็น Digital Twin จริงหรือไม่? (ยังไม่ใช่ เป็น simulator ที่เตรียมสถาปัตยกรรมเผื่อ)
6. เชื่อถือว่า RL เก่งกว่าวิธีอื่นได้หรือยัง? (ยังไม่ได้จนกว่าจะมี held-out benchmark และ uncertainty intervals)
7. เกี่ยวข้องกับองค์การเภสัชกรรมอย่างไร? (บริบทผู้ฟัง ไม่ใช่ข้อมูล ระบบ หรือผลงานอย่างเป็นทางการ)
